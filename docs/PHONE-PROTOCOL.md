# WVC Phone — протокол телефон ↔ WVC (v2 в WVC 0.11: + H.264; v1 (JPEG) по-прежнему работает в обе стороны)

Телефон (приложение WVC Phone, Android) — **сервер**. WVC на Windows — клиент.
Все числа — little-endian. Звука нет.

## Транспорт: Wi-Fi или USB-кабель

- **Wi-Fi** — WVC подключается к `IP телефона:47800`.
- **USB (v0.9)** — как scrcpy: WVC запускает `adb` (из папки `adb\` рядом с WVC.exe, иначе из `PATH`),
  скрыто и с тайм-аутом:
  1. `adb devices -l` — найти телефон (состояния `device` / `unauthorized` / `offline`; модель из `model:`
     или `adb -s <serial> shell getprop ro.product.model`);
  2. `adb -s <serial> forward tcp:<local> tcp:47800` — `<local>` = порт существующего проброса этого телефона,
     иначе 47800, если свободен, иначе `forward tcp:0 tcp:47800` (adb выбирает свободный порт и печатает его);
  3. TCP на `127.0.0.1:<local>` — дальше тот же протокол. На телефоне подключение приходит от `127.0.0.1`
     (adbd), поэтому сервер слушает все интерфейсы, включая loopback.
  Если соединение закрылось без единого сообщения — приложение на телефоне не запущено:
  WVC выполняет `adb shell am start -n com.wvc.phone/.MainActivity` (не чаще раза в 15 с) и повторяет.
  При отключении/выходе — `adb forward --remove tcp:<local>`; `adb kill-server` при выходе, только если
  сервер adb запустил сам WVC.
  Поиск по UDP в режиме USB не используется.

## Поиск (UDP 47801)

1. WVC шлёт UDP-датаграмму `WVCP?` (5 байт ASCII) на порт **47801**: на `255.255.255.255` и на
   широковещательный адрес каждой IPv4-сети компьютера (3 раза с интервалом 0,5 с), затем ~2 с слушает ответы.
2. Телефон отвечает на адрес/порт отправителя: `WVCP!<имя>` — имя устройства (UTF-8, напр. `Samsung SM-S911B`).
3. IP телефона WVC берёт из адреса отправителя ответа. IP можно ввести и вручную (он крупно показан в приложении).

## Соединение (TCP 47800)

WVC подключается к `IP:47800`. Одновременно один клиент: новое подключение вытесняет старое.
Сразу после подключения WVC шлёт свои `SRC …` и `RES …` (WVC 0.11 — сначала `CODEC h264`, см. ниже),
телефон — `NAME …`, `RES …`, `STATE …`.

### Телефон → WVC: сообщения с заголовком

| Поле | Размер | Значение |
|---|---|---|
| magic | 4 | `WVCF` — кадр JPEG, `WVCH` — пакет H.264 (v2), `WVCS` — текстовое сообщение |
| length | uint32 | длина полезной части (JPEG, H.264 или текст) |

**Кадр `WVCF`** — после `length` ещё 5 байт, затем JPEG:

| Поле | Размер | Значение |
|---|---|---|
| width | uint16 | ширина JPEG (как закодирован, до поворота; справочно) |
| height | uint16 | высота JPEG (справочно) |
| rotation | uint8 | 0..3 — на сколько раз по 90° **по часовой** повернуть картинку, чтобы она стала прямой |
| jpeg | length | JPEG (baseline), качество 40–80 (v0.10: снижается само, если сеть не успевает) |

Камера отдаётся как её даёт сенсор + `rotation` (из CameraX `rotationDegrees` с учётом того, как держат телефон);
экран — уже прямой (`rotation = 0`). Размер по длинной стороне ~720 (по умолчанию) или ~1080.
До 30 кадров/с. Кадры **не копятся**: очередь на отправку — один кадр; пока предыдущий отправляется, ждущий
заменяется более новым (минимальная задержка).

v0.10 (только телефон, формат тот же, WVC 0.9 и WVC Phone 0.9 совместимы с 0.10): камера — CameraX
ImageAnalysis `YUV_420_888` + `STRATEGY_KEEP_ONLY_LATEST`, размер ровно 1280×720 / 1920×1080 (или ближайший
меньший), частота кадров камеры 30 (`CONTROL_AE_TARGET_FPS_RANGE`, ближайший диапазон до 30). Копия в NV21 —
на потоке анализа (с учётом rowStride/pixelStride), JPEG — на отдельном потоке (всегда самый новый кадр),
отправка — на третьем.
Если экран телефона не меняется, кадров может не быть — WVC держит последний.


**Пакет `WVCH` (v2, только после `CODEC h264`)** — после `length` ещё 14 байт, затем данные:

| Поле | Размер | Значение |
|---|---|---|
| flags | uint8 | бит 0 — в пакете SPS/PPS, бит 1 — ключевой кадр (IDR). Сейчас ключевой = 3 (SPS/PPS всегда перед IDR) |
| rotation | uint8 | 0..3 — поворот по часовой ×90°, как у `WVCF` (экран — 0) |
| width | uint16 | ширина кадра энкодера |
| height | uint16 | высота |
| pts | uint64 | время кадра, мкс (MediaCodec `presentationTimeUs`) |
| data | length | один кадр H.264 в Annex-B (стартовые коды `00 00 00 01`) |

Телефон: `MediaCodec` `video/avc` с входной поверхностью (`createInputSurface`): камера — CameraX `Preview`
рисует прямо в неё, экран — `VirtualDisplay` рисует в неё (копий через процессор нет). Baseline (если
энкодер не принимает профиль — без него), 30 к/с, ключевой кадр каждую секунду, повтор последнего кадра
через 100 мс (неподвижный экран тоже шлёт кадры), битрейт: 1080p 4–8 Мбит/с, 720p 2–4 Мбит/с — снижается
на 25 %, если очередь растёт, и растёт на 10 %, если сеть успевает. Пакеты идут **все и по порядку**; если
очередь > 45 пакетов или > 4 МБ — очередь сбрасывается и пакеты пропускаются до следующего ключевого кадра
(он запрашивается сразу). При новом подключении и после `CODEC h264` первым идёт ключевой кадр.
Изменение размера/поворота: новый `width`/`height`/`rotation` в пакетах (+ ключевой кадр с новыми SPS/PPS
после перезапуска энкодера) и `STATE`/`RES` как раньше.

**Текст `WVCS`** — UTF-8, одна строка без `\n`:

| Сообщение | Смысл |
|---|---|
| `NAME <имя>` | имя устройства |
| `STATE back` / `STATE front` / `STATE screen` | что сейчас показывается |
| `STATE need_consent` | выбран экран, но Android ещё не дал разрешение на запись экрана (кадров нет) |
| `STATE camera_error` | камеру не удалось открыть (нет такой камеры, занята) |
| `STATE no_camera_permission` | нет разрешения на камеру |
| `RES 720` / `RES 1080` | текущее качество |
| `CODEC h264` / `CODEC jpeg` | (v2) ответ на `CODEC`: каким способом телефон шлёт кадры. `CODEC jpeg` без запроса — на телефоне нет рабочего H.264-энкодера, дальше `WVCF` |
| `STATE back_screen` / `STATE front_screen` | (v2) «камера через экран»: камера во весь экран телефона, передаётся экран |
| `STATE need_activity` | (v2) для «камеры через экран» нужно открыть WVC Phone на телефоне |

`STATE` повторяется каждые 2 с — это и проверка связи: если от телефона ничего нет 7 с, WVC переподключается.

### WVC → телефон: текстовые строки

UTF-8, каждая заканчивается `\n`:

| Команда | Действие |
|---|---|
| `SRC back` | задняя камера |
| `SRC front` | передняя камера |
| `SRC screen` | экран телефона (без разрешения — `STATE need_consent` и запрос на телефоне) |
| `RES 720` / `RES 1080` | длинная сторона картинки |
| `CODEC h264` | (v2) перейти на H.264 (`WVCH`); телефон отвечает `CODEC h264` и начинает с ключевого кадра. WVC шлёт это первым, только если у Windows есть декодер H.264 (Media Foundation) и в источнике выбрано «Авто» |
| `CODEC jpeg` | (v2) обратно на JPEG |
| `KEY` | (v2) нужен ключевой кадр (WVC отстал и сбросил очередь) |
| `SRC back_screen` / `SRC front_screen` | (v2) «камера через экран» (нужно разрешение на запись экрана и открытое приложение) |

Неизвестные команды телефон игнорирует: старый WVC Phone (0.10) на `CODEC h264` не отвечает и шлёт `WVCF` —
WVC 0.11 показывает JPEG. Старый WVC (0.10) не шлёт `CODEC` — WVC Phone 0.11 работает с ним по JPEG.

## Поведение WVC (v0.11)

- Источник «Телефон» может быть в любой сцене, их может быть несколько (разные телефоны); одинаковое
  подключение (тот же IP или тот же телефон на кабеле) открывается один раз и делится между источниками.
- Подключается, пока источник виден в «Сейчас» (в эфире или в живом предпросмотре), в «Следующем», открыты
  его свойства или после «Подключить». Повтор каждые 3 с. «Отключить» — до «Подключить» или следующего «Старт».
- H.264: приём и распаковка — разные потоки. Распаковка — Media Foundation H.264 decoder MFT (низкая
  задержка), NV12 → BGRA; в картинку переводится только последний кадр очереди. Отстаёт больше чем на ~1,5 с
  (45 пакетов) — очередь сбрасывается до ключевого кадра и телефону уходит `KEY`. Нет декодера или ~3 с одни
  ошибки — переподключение в JPEG.
- JPEG: декодируется только самый новый принятый кадр (WIC, с поворотом).
- Состояние: кодек, «приём» (кадров/с с телефона), «показ» (распаковано кадров/с), Мбит/с, размер.
- Автоориентация: когда картинка телефона из вертикальной становится горизонтальной (или наоборот), рамка
  источника поворачивается вокруг центра (ширина ⇄ высота); форма следует рамке.
- Настройки — в источнике сцены (`settings.ini`, раздел `[Scene N Item M]`): `PhoneConn` (0 Wi-Fi, 1 USB),
  `PhoneIp`, `PhoneSerial`, `PhoneSrc` (0 задняя, 1 передняя, 2 экран), `PhoneRes` (0 = 720, 1 = 1080),
  `PhoneCodec` (0 авто/H.264, 1 JPEG, 2 камера через экран), `AutoRotate`.
